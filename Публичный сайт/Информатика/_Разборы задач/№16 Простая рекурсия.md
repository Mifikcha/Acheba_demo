# Пример 1)

![[_Resours/Pasted image 20241102133919.png]]

Итак, тут долго думать не надо, все уже написано за нас. Определяем такую функцию, которая будет выдавать `1`, когда `n = 1` и
`(n - 1) * F(n - 1)` когда `n > 1`:

```python
def f(n):
    if n == 1:
        return 1
    elif n > 1:
        return (n-1) * f(n-1)
```

Обратите внимание: действуем мы именно через return, что у самой функции по итогу было значение.

Затем выведем значение выражения из условия:

```python
print((f(2024) + 2*f(2023)) // f(2022))
```

Проверьте порядок операций: пропущенные скобки изменят результат и могут значительно увеличить время вычисления. Например, без внешних скобок выражение выглядит так:

```python
print(f(2024) + 2*f(2023) // f(2022))
```

И порядок действий был бы уже другой.

В первом случае:
- Умножение: `2 * f(2023)`
- Деление: `(2 * f(2023)) // f(2022)`
- Сложение: `f(2024) + ((2 * f(2023)) // f(2022))`

Во втором случае:
- Умножение: `2 * f(2023)`
- Сложение: `f(2024) + (2 * f(2023))`
- Деление: `(f(2024) + 2 * f(2023)) // f(2022)`

Это приводит к более длительным вычислениям и неправильному ответу.

Объединим код:

<div class="python-checker" data-title="Пример 1" data-code="def f(n):&#10;    if n == 1:&#10;        return 1&#10;    elif n &gt; 1:&#10;        return (n-1) * f(n-1)&#10;print((f(2024) + 2*f(2023)) // f(2022))"></div>

Однако, если мы попытаемся запустить такой код, питон выдаст нам ошибку:

`RecursionError: maximum recursion depth exceeded`

Это означает, что глубина вызовов превысила установленный в Python предел. Функция `sys.setrecursionlimit()` повышает этот предел; для данного примера используется $10^6$. Повышение предела не устраняет риск нехватки памяти при очень глубокой рекурсии.

<div class="python-checker" data-title="Пример 1" data-code="import sys&#10;sys.setrecursionlimit(10**6)&#10;  &#10;def f(n):&#10;    if n == 1:&#10;        return 1&#10;    elif n &gt; 1:&#10;        return (n-1) * f(n-1)&#10;  &#10;print((f(2024) + 2*f(2023)) // f(2022))"></div>

Вот такой код выдаст нам ответ.

**_Ответ:_** 4094550.

# Пример 6)

![[_Resours/Pasted image 20260828151047.png|1448]]

Вот и кончилась лафа. Здесь у нас две проблемы:

* Большие числа, глубина рекурсии будет большой, какой бы `sys.setrecursionlimit` мы ни ставили
* Две функции одновременно

Первое решается очень просто - кэшированием.

> [!note]- Кэширование
>
> Кэширование — это когда Python **запоминает уже посчитанные значения функции**.
>
> Вот эта строка:
>
> ```python
> @lru_cache(None)
> ```
>
> говорит:
>
> > если функцию уже вызывали с таким `n`, не считай заново, просто верни готовый ответ из памяти.
>
> Например, если один раз посчитали:
>
> ```python
> G(22549)
> ```
>
> то при следующем вызове:
>
> ```python
> G(22549)
> ```
>
> Python уже не будет снова идти по рекурсии, а сразу достанет ответ.
>
> ---
>
> В твоём коде это нужно особенно для `G(n)`:
>
> ```python
> def G(n):
>     if n >= 22560:
>         return n // 23 + 33
>     if n < 22560:
>         return G(n + 11) - 4
> ```
>
> `G(n)` идёт **вверх**:
>
> ```text
> G(1) → G(12) → G(23) → ... → G(22560+)
> ```
>
> Без кэша каждый вызов `G(...)` заново проходил бы длинную цепочку.
>
> А ты заранее делаешь:
>
> ```python
> for n in range(22560, 0, -1):
>     G(n)
> ```
>
> Предварительно вычисляем значения `G(n)` и сохраняем их в кэше.
>
> Потом, когда вызывается:
>
> ```python
> print(F(548))
> ```
>
> внутри `F` рано или поздно будет:
>
> ```python
> G(n - 7)
> ```
>
> И `G(...)` уже не будет долго считаться — значение почти наверняка уже лежит в кэше.
>
> ---
>
> Коротко:
>
> ```text
> `lru_cache` позволяет повторно использовать уже вычисленные значения функции.
> ```
>
> А цикл:
>
> ```python
> for n in range(22560, 0, -1):
>     G(n)
> ```
>
> нужен, чтобы заранее заполнить кэш значениями `G`.
>
> Итог: код работает быстро и не умирает от длинной рекурсии.
>
А что касается второй проблемы, то принципиально ничего не меняется. Просто пишем эту вторую функцию и все тут. По итогу:

<div class="python-checker" data-title="Пример 6" data-code="from functools import lru_cache&#10;&#10;@lru_cache(None)&#10;def F(n):&#10;    if n &gt;= 21:&#10;        return F(n - 8) + 1095&#10;    if n &lt; 21:&#10;        return 10 * (G(n - 7) - 36)&#10;&#10;@lru_cache(None)&#10;def G(n):&#10;    if n &gt;= 22560:&#10;        return n // 23 + 33&#10;    if n &lt; 22560:&#10;        return G(n + 11) - 4&#10;&#10;for n in range(22560, 0, -1): # Обратный порядок позволяет заполнить кэш с нужной стороны&#10;    G(n)&#10;&#10;print(F(548))"></div>

# Пример 7)

![[_Resours/Pasted image 20260828151942.png|1448]]

Здесь ни кэширование (которое `None`) ни рекурсия не помогут, числа слишком большие. Чтобы понять в чем проблема, давайте вернемся к одному из примеров выше, на маленькие числа и детально проследим как питон считает подобные задачи. Возьмем вот этот код:

<div class="python-checker" data-title="Пример 7" data-code="def F(n):&#10;    if n &gt;= 2025:&#10;        return n&#10;    if n &lt; 2025:&#10;        return n + F(n + 2) &#10;print(F(2022) - F(2023))"></div>

1) Когда запускается программа первое, что делает питон - это `print(F(2022) - F(2023))`. Он понимает, что вызывается функция, знает, что это за функция, но не знает ее значений. Соответственно, идет их считать именно с чисел `2022` и `2023`.
2) Далее, он смотрит на функцию и попадает в условие `if n < 2025:`. А там снова функции, но уже `n + F(n + 2)`.
3) Теперь он считает эту же функцию, но от чисел `2024` и `2025`.
4) И так далее, пока он не воткнется обоими числами в первое условие `if n >= 2025:` и не поймет, что ему известны оба значения функции без вызова ее же еще раз.

Вывод: эти задачи питон считает С КОНЦА. И каждое его действие "вызов функции в функции" т.е. пункты 2-4 - это либо нагрузка на процессор, если речь про рекурсию, либо на оперативку, если речь про `lrucache`.

> [!note] Теперь в чем проблема:
> От числа `257487` до ближайшего известного значения при `n = 10` потребуется ***51 496*** шагов с шагом `5`. Прямое рекурсивное вычисление и кэширование всех промежуточных значений потребуют значительных ресурсов.

> [!tip] Спойлер решения проблемы
> Задать опорные значения функции вблизи начала вычислений.

Поэтому, мы воспользуемся ***темной магией: переформулируем задачу.***

Можно заметить классную вещь:

$$
F(257487)=(257487+4)*F(257487-5)=(257487+4)*(257482+4)*F(257482-5)=\dots*F(257472)
$$

Функции связаны между собой; при делении одинаковые множители сокращаются. Рассмотрим выражение:

$$
\frac{\frac{F(257487)}{683}+67*F(257477)}{F(257472)}
$$

Знаменатель вообще можно не считать, он все равно сократиться. А вверху останутся вполне адекватные значения функции. Таким образом, мы только что переписали задачу до вот такого вида:

$$
F(257487) / F(257472) / 683 + 67 * F(257477) / F(257472)
$$

Поэтому вместо того, чтобы считать знаменатель мы скажем: `F(257472) / F(257472) = 1`. **Так задаём программе известное опорное значение.**

<div class="python-checker" data-title="Пример 7" data-code="def f(n):&#10;    if n == 257472:&#10;        return 1 # Можно любое число написать&#10;    return (n+4)*f(n-5)&#10;print(f(257_487) / 683 + 67 * f(257477) / f(257472))"></div>

Если есть желание закэшировать эту задачу - это можно, но кэшировать, по вышесказанному, нужно НЕ все значения. Например, можно сделать так:

<div class="python-checker" data-title="Пример 7" data-code="from functools import *&#10;&#10;@lru_cache(100)&#10;def f(n):&#10;    if n &lt; 10:&#10;        return 3&#10;    return (n + 4) * f(n - 5)&#10;&#10;for i in range(10, 257490):&#10;    f(i)&#10;&#10;print((f(257_487) // 683 + 67 * f(257_477)) / f(257_472))"></div>
